# Three finite strengthening actions (proposals only)

The completed paper is the deliverable. None of the actions below was executed or added to an automatic queue. These are estimates and proposed ceilings, not existing measurements or authorization. Prefer action 2 when only one engineering comparison can be added; choose action 1 if fixed-missingness comparative strength is the decisive concern. Do not extend the Full branch bank.

1. **Same-protocol learning comparisons.** Reuse qualified MLP/CNP source weights on the original 30% random/block/boundary masks and exact mask seeds, table cohorts, and inside/outside classification. Check fitting/selection identities first; reproduce Full by record aggregation before any inference. If adding one model, use ANP or explicitly named deterministic attentive conditional regression, with matched source data, visible labels, validation opportunities, and reported compute/convergence. Assets: original mask records, input geometry/material schema, qualified checkpoints and training receipts. Proposed cap: 8 CPU core-hours for existing-model evaluation and finite source-validation adaptation selection; a new conditional model requires its own separate plan (provisional maximum 4 GPU-hours), not automatic spending. Stop after the declared comparison, or on absent qualified weights/label isolation. Report every condition with `unified.aggregate` semantics.

2. **Native strong-baseline loop.** Check that MLP fitting and selection excluded all original 84 native holdout tables; confirmation-table evaluation does not establish this. Reuse an eligible checkpoint and the selected GP. Generate on the same native S/Q, export using the same replacement rules, and run exactly eight layouts × B4/B8 × three seeds for each method (96 candidate runs total). Compare net-C, absolute worst-slack and P99 endpoint-slack errors, plus target fitting/completion costs. Assets: excluded-ID lists, weights, native S/Q manifests, rules, routed databases, tool/library/constraint provenance. Proposed cap: 8 CPU core-hours and 5 GB additional artifacts; 1 CPU core-hour is reserved within that cap for a qualification/pilot check. If checkpoint provenance fails, stop and estimate necessary retraining separately. No automatic retraining or extra layouts. This directly tests whether strong table-level alternatives translate into engineering fidelity.

3. **Geometry-stratified extrapolation analysis.** First check stored S, Q, coordinates, predictions and output components for all compared methods on the same records. Use interval distance divided by support span for rank one and distance to the support convex hull under a fixed coordinate scale for rank two, explicitly handling degenerate supports. Freeze geometric bins before comparing errors. Assets: per-point predictions and support/query identities, not aggregate scores alone. Proposed cap: 2 CPU core-hours for record-only derivation. If fields are incomplete, deliver a missing-asset list and a bounded inference estimate rather than fabricating distance strata or automatically re-running models. No model/threshold search.

Analytic physical fitting and end-to-end characterization cost measurement are not compulsory additions to this accuracy/interface paper. They become relevant only if the headline is changed to physics-based extrapolation or measured characterization savings.
